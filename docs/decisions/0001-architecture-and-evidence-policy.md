# 0001: Architecture, evidence policy, and ranking

Date: 2026-10-01

## Context

The goal is a guide to oxidative stress that helps a person choose diet, exercise, and lifestyle changes, with a separate focus on oxidative damage to sperm (DNA fragmentation) and eggs (oocyte quality). It has to be grounded in peer-reviewed research rather than health websites, show how much of something is needed, explain mechanisms (including redundancy, e.g. several Nrf2 activators at once), and run as a GitHub Pages site behind a simple passphrase for a friends-only beta.

## Decisions

### Static site, no build toolchain
Plain `index.html` + `app.js` + `style.css`, hash routing, one merged `assets/data.json`. The only external dependency is `marked` (cdnjs) for rendering the long-form notes. **Why:** GitHub Pages serves it directly, nothing to install, and the content (JSON + markdown) can be edited by hand or regenerated by research passes. **Rejected:** React/Vite (needs Node, which this machine doesn't have installed, plus a CI build for Pages); a static site generator (Jekyll/Hugo templates make the interactive compare/plan views awkward).

### Research split into five areas, each owning a JSON + markdown pair
`foundations` (biology, biomarkers, supplement trials), `diet`, `lifestyle` (exercise, sleep, smoking, environment), `sperm`, `egg`. Each was researched independently against `research/SCHEMA.md`. **Why:** each area has its own literature and its own outcome measures (F2-isoprostanes vs sperm DNA fragmentation index vs IVF live birth), and keeping the narrative next to the structured data means every rating has a written justification.

### Merging: one page per factor, one section per area
The same lever often appears in several areas (smoking matters for general oxidative stress, sperm, and eggs, with different papers and effect sizes). `tools/build.py` groups entries by id after applying `data/aliases.json`, and the factor page shows each area's section separately rather than blending text. Score ownership: only `foundations`/`diet`/`lifestyle` may set the **general** impact; `sperm` and `egg` own their scopes, and general areas can fill a fertility scope only when the fertility area didn't cover the factor. **Why:** the fertility researchers assigned "general" scores outside their remit; letting them override would mix up the rankings.

"Harmful exposure" and "beneficial action" versions of the same lever stay as separate factors when both exist (`excess-adiposity` vs `weight-loss`; `varicocele` vs `varicocele-repair`) so each factor has one consistent direction.

### Evidence policy
- Every reference must be verified to exist. `tools/verify_refs.py` independently re-fetches every PMID from NCBI E-utilities (and DOI-only refs from Crossref), checks title similarity ≥ 0.75, year within ±1, DOI match, and **flags retracted publications** that aren't labelled as retracted in the data. The research passes found several retracted trials (Hajizadeh Maleki exercise/sperm trials, Ismail 2014 L-carnitine, Pacchiarotti 2016 myo-inositol + melatonin) and either excluded them or kept them explicitly marked; Safarinejad's trials were excluded because of his retraction record.
- No ORAC/FRAP/TEAC scores. In-vitro antioxidant capacity doesn't predict in-vivo effect, and the USDA withdrew its ORAC database in 2012. Polyphenol content (Phenol-Explorer) is shown only as context, with an explicit "content is not benefit" notice in the compare view.

### Ranking = impact × evidence weight
Impact is an editorial 0–5 judgment of human effect size per scope; evidence is strong/moderate/limited/mechanistic with weights 1.0/0.8/0.55/0.3. **Why:** a pure impact ranking would put mechanistically exciting but untested things (NMN, MitoQ) next to smoking cessation. **Rejected:** a numeric effect-size meta-model. The outcomes aren't commensurable (percent change in F2-isoprostanes vs points of DNA fragmentation index vs odds ratio for live birth), so a single computed number would be false precision.

### Passphrase gate is obscurity, not security
SHA-256 of the lowercased passphrase is compared in the browser; success is remembered in localStorage. The repo is public (free GitHub Pages requires it), so the data is readable on GitHub anyway; the user explicitly accepted this. `noindex` meta keeps search engines away. Change it with `python tools/set_passphrase.py <phrase>`. **Rejected:** encrypting `data.json` with a key derived from the passphrase (staticrypt-style). It would add a build step and wouldn't hide the source data in the public repo.

### Guided plan
`data/guide.json` defines questions whose answers boost, hide, or annotate factors. The plan ranks by the best impact × evidence across the chosen goals plus answer boosts. Supplements with weak, null, or mixed evidence go into a separate "probably skip" list unless an answer makes them relevant (e.g. CoQ10 for IVF poor responders). Non-actionable factors (age, chemotherapy) are excluded unless an answer brings them in. All answers stay in the browser.
